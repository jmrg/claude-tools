# Configuración: perfiles `cops` y `cdev` (dos modos de trabajo de Claude Code)

> **Cómo usar este archivo.** Pásaselo a Claude Code con: *"Lee este archivo y ejecuta la configuración en mi equipo, paso a paso, siguiendo sus reglas y pidiéndome confirmación antes de modificar archivos existentes."*
> Escrito para **Windows** (archivos `.cmd`, funcionan en CMD y en PowerShell). Versión: 2026-11-17.

## 0. Reglas para Claude (léelas antes de actuar)

1. **Solo se crean archivos nuevos:** 2 perfiles `.json` en `~/.claude/profiles/` y 4 `.cmd` en una carpeta `bin` del usuario. **No modifiques `settings.json` ni `CLAUDE.md`.** Si un archivo de destino ya existe, muestra las diferencias, respáldalo en `~/.claude/backups/` y espera confirmación.
2. **PATH:** agregar la carpeta `bin` al PATH **de usuario** requiere confirmación explícita (paso 5). No toques el PATH del sistema.
3. **Escritura:** usa Write/Edit (UTF-8 sin BOM). Prohibido `Set-Content`, `Out-File` y `>` para JSON y `.cmd` (Windows PowerShell 5.1 escribe BOM o UTF-16 y rompe el JSON).
4. **No bloquees la terminal:** no agregues `PowerShell` ni `Bash` a `permissions.deny` en ningún perfil. En sesiones normales de Windows la única terminal es PowerShell; bloquearla deja la sesión sin shell.
5. **Nada sensible:** no pidas ni escribas contraseñas, tokens ni claves.
6. **Cada paso termina con una comprobación con salida esperada.** Si no coincide, detente y reporta el error literal y el paso.
7. Las pruebas que gastan modelo (paso 7) son **opcionales** y solo con confirmación y con tope de costo.

## 1. Qué se configura y para qué

Dos comandos que arrancan Claude Code con un **perfil** distinto (modelo, esfuerzo, advisor y modelo de subagentes), sin cambiar la configuración global:

| Comando | Para qué | Modelo | Esfuerzo | Advisor | Subagentes |
|---|---|---|---|---|---|
| `cops` (`claude-ops`) | Operación y día a día: revisar errores, logs, pipelines, servidores | `sonnet` | medium | `opus` (`advisorModel`) | `haiku` |
| `cdev` (`claude-dev`) | Desarrollo e investigación: entender e implementar cosas complejas | `opus[1m]` | medium | apagado | `inherit` |
| `claude` (sin perfil) | Lo que diga `settings.json` | el global | el global | el global | igual que la sesión |

La idea: el trabajo rutinario corre con un modelo más barato que **consulta a uno fuerte solo cuando hace falta** (advisor), y el trabajo difícil corre directamente con el modelo fuerte.

Cómo funciona: `claude --settings <perfil>.json` **se suma** a `settings.json` y gana en las claves que repite. Los hooks, plugins y permisos globales se heredan en ambos perfiles.

## 3. Variables (calcúlalas, repórtalas y úsalas en todos los pasos)

| Variable | Valor por defecto | Nota |
|---|---|---|
| `PERFILES` | `$HOME/.claude/profiles` | Se crea si falta |
| `BIN` | `$HOME/bin` | Carpeta de los `.cmd`; si ya está en el PATH de usuario, úsala |
| `WORKDIR` | **Pregunta al usuario** | Carpeta de trabajo de confianza (ver abajo). Ruta absoluta con `\` |

**Por qué existe `WORKDIR`.** Claude Code no recuerda la confianza de la carpeta de usuario (`$HOME`): si se abre ahí, pregunta en cada arranque. Los comandos, si se ejecutan **desde `$HOME`**, cambian a `WORKDIR` antes de abrir Claude; desde cualquier otra carpeta no cambian nada, y la consola del usuario conserva su carpeta. Además, así la sesión usa la memoria y los permisos de **ese** proyecto y no los del home. Elige una carpeta que el usuario ya use como espacio de trabajo y que exista.

**Comprobación:** `WORKDIR` existe (`Test-Path`). Si no, detente y pregunta de nuevo.

## 4. Crear los perfiles

Crea `$PERFILES/ops.json`:

```json
{
  "model": "sonnet",
  "advisorModel": "opus",
  "effortLevel": "medium",
  "env": {
    "CLAUDE_CODE_SUBAGENT_MODEL": "haiku"
  }
}
```

Crea `$PERFILES/dev.json`:

```json
{
  "model": "opus[1m]",
  "effortLevel": "medium",
  "env": {
    "CLAUDE_CODE_SUBAGENT_MODEL": "inherit",
    "CLAUDE_CODE_DISABLE_ADVISOR_TOOL": "1"
  }
}
```

**Comprobación:** para cada archivo, `node -e "JSON.parse(require('fs').readFileSync(process.argv[1],'utf8'))" "<ruta>"` termina sin error y el archivo **no** empieza por BOM (`EF BB BF`).

## 5. Crear los comandos y el PATH

Crea `$BIN/claude-ops.cmd` (sustituye `WORKDIR` por la ruta real, con `\`):

```bat
@echo off
setlocal
if /i "%CD%"=="%USERPROFILE%" cd /d "WORKDIR"
set "PERFIL=%USERPROFILE%\.claude\profiles\ops.json"
if "%~1"=="" (claude agents --settings "%PERFIL%") else (claude --settings "%PERFIL%" %*)
endlocal
```

Crea `$BIN/claude-dev.cmd`: **igual, cambiando `ops.json` por `dev.json`.**

Crea `$BIN/cops.cmd`:

```bat
@echo off
claude-ops %*
```

Crea `$BIN/cdev.cmd`:

```bat
@echo off
claude-dev %*
```

Comportamiento que implementan (no lo cambies sin motivo):
- **Sin argumentos** abren la vista de agentes (`claude agents`), igual que `claude` a secas, con el perfil.
- **Con argumentos** abren un chat con el perfil y pasan los argumentos tal cual: `cops -c`, `cdev --resume <id>`, `cops -p "..."`.
- `cd` no se usa como alias porque es el comando de cambio de carpeta.

**PATH de usuario.** Si `BIN` no está en el PATH **de usuario**, pide confirmación y agrégala conservando lo existente, **sin `setx`** (trunca a 1024 caracteres):

```powershell
$p = [Environment]::GetEnvironmentVariable('Path','User')
if (($p -split ';') -notcontains "$HOME\bin") { [Environment]::SetEnvironmentVariable('Path', ($p.TrimEnd(';') + ";$HOME\bin"), 'User') }
```

Las ventanas ya abiertas no lo ven: hay que abrir una terminal nueva.

**Comprobación (en terminal nueva):** `(Get-Command cops).Source` y `(Get-Command cdev).Source` devuelven rutas dentro de `BIN`, y `cops --version` imprime la versión de Claude Code (sin gastar tokens).


## 8. Qué NO se verificó / límites conocidos

- **Advisor solo en `cops`, modelo de los subagentes y esfuerzo efectivo en sesión interactiva:** no están verificados. Se comprueban dentro de una sesión (`/advisor`, lanzar un subagente de prueba, `/config`).
- **Permisos del home:** las reglas de permisos que el usuario tenga en `~/.claude/settings.local.json` **solo aplican a sesiones abiertas en `$HOME`**. Como los comandos cambian a `WORKDIR`, esas reglas **no aplican** en `cops` ni en `cdev`. No las copies en bloque a los perfiles: suelen incluir comandos amplios o destructivos. Si hace falta, agrega a `ops.json` una lista corta y curada de comandos de **solo lectura**.
- **Los perfiles no pueden quitar un `deny` global:** los bloqueos se suman.
- **El advisor** solo funciona contra la API de Anthropic y se apaga si se desactiva la telemetría (`DISABLE_TELEMETRY`). `--advisor` no aparece en `claude --help` pero está documentado.
- **Subagentes:** `CLAUDE_CODE_SUBAGENT_MODEL` no afecta a los agentes integrados Explore y Plan, y el `model` del frontmatter de un agente propio tiene prioridad sobre la variable (ver `4.reglas-de-agentes.md`).
- Mientras `cops` use `haiku` para subagentes y `cdev` use `inherit`, un agente propio con `model:` fijo ignora ambos.
- Si `claude` en tu instalación es un `.cmd` y no un `.exe`, el wrapper no vuelve a ejecutar `endlocal`: es inofensivo (el entorno muere con el proceso).
- **Ajuste sugerido, no aplicado:** `effortLevel: high` en `dev.json`; con `medium` queda igual que `claude` a secas si el global también es `medium`.
