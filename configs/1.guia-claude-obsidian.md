# Guía de configuración: Claude Code + vault de Obsidian (memoria de contexto extendida)

> **Cómo usar este archivo.** Pásaselo a Claude Code con: *"Lee este archivo y ejecuta la configuración en mi equipo, paso a paso, siguiendo sus reglas y pidiéndome confirmación antes de modificar archivos existentes."*
> Está escrito para que lo ejecute Claude Code en **Windows** (Windows PowerShell 5.1 y Node.js), y también se puede seguir a mano. Versión de la guía: 2026-11-17.

## 0. Reglas para Claude (léelas antes de actuar)

1. **Respalda antes de modificar** `settings.json` y `CLAUDE.md` (paso 4).
2. **Muestra el diff o el bloque a insertar y espera confirmación** antes de editar cualquier archivo existente. Nunca sobrescribas: fusiona.
3. **Alcance:** solo `~/.claude/` y el vault. No instales nada. No ejecutes nada fuera de ahí, salvo comandos de lectura para diagnosticar.
4. **Escritura de archivos:** usa solo las herramientas Write/Edit (UTF-8 sin BOM). **Prohibido** `Set-Content`, `Out-File`, `Add-Content`, `>` y `>>` para notas, scripts y JSON: en Windows PowerShell 5.1 escriben ANSI, UTF-8 con BOM o UTF-16, y una nota así pierde su frontmatter en el índice sin dar error.
5. **JSON:** nunca uses `ConvertFrom-Json`/`ConvertTo-Json` sobre `settings.json` (con la profundidad por defecto destruye los hooks). Usa `vault-settings.js` (paso 7).
6. **Comandos:** sin `&&` ni `||` (Windows PowerShell 5.1 no los tiene); sin `~` (no se expande al llamar a programas; usa `"$HOME/..."` entre comillas); sin herramientas de Unix (`wc`, `grep`, `cat`...). Rutas con `/`.
7. **Nada sensible:** no pidas ni escribas contraseñas, tokens ni claves; no copies datos de clientes, proveedores ni de otras personas al vault.
8. **Cada paso termina con una comprobación con salida esperada.** Si lo obtenido no coincide, detente.

**Detente y reporta el error literal y el paso** cuando: un comando termine con código ≠ 0; veas `HASH DISTINTO`, `JSON inválido` o `DISTINTO, no se toca`; `node --version` sea menor que 18; la salida no coincida con la esperada; o el usuario no haya confirmado. Después propón una corrección; no improvises cambios fuera de lo descrito.

**Al terminar**, entrega un resumen: archivos creados o modificados, ruta del respaldo, resultado de cada verificación (T1 a T6) y pendientes.

## 1. Qué se configura y para qué

| Capa | Qué es | Para qué sirve |
|---|---|---|
| **Vault de Obsidian** | Carpeta de notas Markdown con frontmatter estándar | Memoria *declarativa* detallada: arquitectura, estado de proyectos, decisiones, pendientes, traspasos |
| **Memoria automática** de Claude Code | `MEMORY.md` + un archivo por memoria | Reglas de comportamiento (`feedback`) y **punteros** de una línea hacia el vault |
| **`~/.claude/CLAUDE.md`** | Instrucciones globales | Le dice a Claude cuándo y cómo leer y escribir el vault |
| **Hook `SessionStart`** + `vault-indices.js` | Script Node | Regenera los índices e **inyecta un índice compacto** al abrir sesión, tras `/clear` y `/compact` |
| **Permisos** en `settings.json` | `permissions.allow` | Claude lee y edita el vault sin pedir confirmación en cada acceso |

Flujo resultante (regla de 2 capas: **vault → código fuente**):

```
Sesión nueva ──hook SessionStart──► vault-indices.js --llm ──► índice compacto en el contexto de Claude
Claude trabaja ─► lee notas relacionadas del vault ─► actúa
Aparece info project/reference ─► Claude escribe/actualiza la nota en el vault ─► regenera índices ─► puntero en memoria automática
```

> **Seguridad.** El vault y la memoria **nunca** contienen credenciales, tokens, contraseñas, claves privadas ni datos de clientes o proveedores (identificadores fiscales, facturas, nómina, datos personales). Anonimiza. Si algo sensible aparece, no lo reproduzcas.
> En equipos administrados por una organización, la red de producción y los sistemas internos siguen sujetos a las autorizaciones de esa organización: esta configuración solo organiza *contexto*, no concede accesos.

## 4. Respaldo

```powershell
$b = "$HOME/.claude/backups/vault-obsidian-" + (Get-Date -Format 'yyyyMMdd-HHmmss')
New-Item -ItemType Directory $b -Force | Out-Null
Copy-Item "$HOME/.claude/settings.json","$HOME/.claude/CLAUDE.md" $b -ErrorAction SilentlyContinue
$b
Get-ChildItem $b | Select-Object Name, Length
```

Esperado: imprime la carpeta de respaldo y lista los archivos que existían (0, 1 o 2). Anota la ruta para el resumen final.

## 5. Extraer los archivos del Anexo A

Los scripts, las plantillas y el bloque de `CLAUDE.md` están en el Anexo A, cada uno con su **SHA256**. No se transcriben a mano: los extrae un programa pequeño (Anexo B) que comprueba cada hash.

1. **Crea el extractor.** Con Write, crea `$HOME/.claude/scripts/vault-extraer.js` con el contenido **exacto** del Anexo B (UTF-8 sin BOM, fines de línea LF, una línea final en blanco).
2. **Verifica el extractor** con `Get-FileHash` y compáralo con el `sha256=` del Anexo B:

   ```powershell
   (Get-FileHash "$HOME/.claude/scripts/vault-extraer.js" -Algorithm SHA256).Hash.ToLower()
   ```

   Si no coincide, reescríbelo una vez; si vuelve a fallar, **detente** y reporta.
3. **Simula** (no escribe nada):

   ```powershell
   node "$HOME/.claude/scripts/vault-extraer.js" "<GUIA>" "$HOME/.claude" "<VAULT>"
   ```

   Esperado: 11 líneas `nuevo` o `igual` y, al final, `OK 11 archivos`.
   - `HASH DISTINTO`: la guía está dañada o editada sin actualizar su hash. **Detente.**
   - `DISTINTO, no se toca`: ya existe un archivo con ese nombre y distinto contenido (por ejemplo, una versión propia del usuario). Muéstrale las diferencias y pregunta si lo conserva o lo reemplaza. Para reemplazarlo, mueve el original a la carpeta de respaldo (`Move-Item`) y repite.
4. **Aplica**, tras la confirmación del usuario:

   ```powershell
   node "$HOME/.claude/scripts/vault-extraer.js" "<GUIA>" "$HOME/.claude" "<VAULT>" --apply
   ```

   Esperado: líneas `escrito` o `igual` y `OK 11 archivos`. Un segundo `node ...` sin `--apply` debe mostrar todo `igual`.

El extractor sustituye `{{CLAUDE_DIR}}` y `{{VAULT}}` en el bloque de `CLAUDE.md`; no toca `{{title}}` ni `{{date:...}}` de las plantillas. Si en el futuro se edita un archivo del Anexo A, hay que recalcular su hash: `node vault-extraer.js <guia> <CLAUDE_DIR> <VAULT> --hashes` imprime los valores reales.

## 6. Crear el vault

1. Crea la estructura (sin sobrescribir lo existente):

   ```
   <VAULT>/
   ├── Indice.md                 ← generado por el script (no editar)
   ├── templates/                ← plantillas (ya extraídas en el paso 5)
   ├── <Area-1>/<Area-1>.md      ← nota-índice homónima, generada
   └── <Area-2>/ ...
   ```

   ```powershell
   New-Item -ItemType Directory "<VAULT>/<Area>" -Force | Out-Null
   ```

   Una carpeta por área. Subcarpetas solo si un área supera ~15 notas. El **estado** del trabajo va en el frontmatter, **no** en carpetas (no crear `Pendientes/` ni `Cerrados/`). La carpeta `Sesiones/` (si algún día se usa para logs automáticos) queda fuera de los índices.

2. **Convención de cada nota** (frontmatter obligatorio + línea de área):

   ```yaml
   ---
   area: <carpeta>            # igual a la ruta relativa de la carpeta
   tipo: sistema|proyecto|analisis|referencia|guia|detalle
   padre: <nota>              # solo si tipo: detalle
   estado: activo|pausado|cerrado|referencia
   actualizado: AAAA-MM-DD
   resumen: "≤100 caracteres"
   tags: []
   ---
   ```

   Reglas del cuerpo:
   - Lo segundo tras el título: `**Área:** [[<nota-índice de su carpeta>]]`.
   - Cada nota empieza con `## Estado actual` (≤ ~40 líneas, **se reescribe**, no se acumula): lo único que hay que leer para retomar.
   - Mínimo **2 wikilinks** por nota (1 en subnotas `detalle`); el script avisa si faltan.
   - Si una nota supera ~20 KB, mueve historial y referencia **tal cual** a subnotas `<nota>-<tema>.md` (`tipo: detalle`, `padre`) con `vault-split-note.js`: `node "$HOME/.claude/scripts/vault-split-note.js" spec.json`, que verifica que no se pierda ni duplique ninguna línea (si falla, no toca la nota original). Formato de `spec.json`:

     ```json
     {
       "source": "<VAULT>/Area/nota.md",
       "mainFile": "<ruta de la versión reescrita y corta de la nota principal>",
       "area": "Area", "parent": "nota", "indexNote": "Area", "date": "AAAA-MM-DD", "tags": ["tag"],
       "subnotes": [{ "name": "nota-bitacora", "title": "Bitácora", "resumen": "≤100 caracteres", "ranges": [[40, 120]] }],
       "discard": [[1, 10]]
     }
     ```

3. **Plantillas.** Los 6 archivos de `<VAULT>/templates/` (uno por `tipo`) ya los creó el paso 5. Contienen `{{title}}` y `{{date:YYYY-MM-DD}}`: el plugin Templates de Obsidian los resuelve; **cuando Claude use una plantilla, debe sustituirlos él** por el título y la fecha reales.

4. **Genera los índices y comprueba:**

   ```powershell
   node "$HOME/.claude/scripts/vault-indices.js" "<VAULT>"
   Test-Path "<VAULT>/Indice.md"
   ```

   Esperado en un vault nuevo: `Índices regenerados: 0 notas, 0 activas, 0 pausadas.` y `True`. Cada vez que crees o cambies una nota, vuelve a ejecutarlo y **revisa sus avisos** (falta `resumen` o `estado`, `area` que no coincide con la carpeta, pocos wikilinks). El script lee notas con BOM UTF-8 o UTF-16, pero la regla 4 sigue vigente.

## 7. `settings.json`: fusionar con `vault-settings.js`

El script lee el archivo (si no existe, parte de `{}`), conserva todas las claves del usuario y agrega solo lo que falta. Es idempotente: ejecutarlo dos veces no cambia nada la segunda.

1. **Simula** (no escribe nada) y muestra la salida al usuario:

   ```powershell
   node "$HOME/.claude/scripts/vault-settings.js" "$HOME/.claude/settings.json" "<VAULT>"
   ```

   Esperado: líneas `+ ...` y `cambios: N`. En un equipo limpio N = 4 (3 permisos y 1 hook). Qué agrega:
   - `permissions.allow`: `Read(<VAULT>/**)`, `Edit(<VAULT>/**)`, `Grep(<VAULT>/**)`.
   - `hooks.SessionStart`: `matcher: startup|resume|clear|compact`, `node "<HOME>/.claude/scripts/vault-indices.js" --llm`, `timeout: 30`. Solo si ningún hook ya llama a `vault-indices.js`. El hook usa ruta absoluta con `/` calculada por el script.
   - Opcionales: `--write` agrega también `Write(<VAULT>/**)` (úsalo si Claude pide permiso al crear notas nuevas); `--memory "<carpeta>"` fija `autoMemoryDirectory` solo si la clave no existe (ver paso 9).
   - Si el archivo existe pero no es JSON válido, imprime `JSON inválido ...` y termina con código 1: **detente**; no intentes repararlo.
2. **Aplica**, tras la confirmación del usuario: repite el comando con `--apply`. Guarda un respaldo `settings.json.bak-<fecha>` y escribe UTF-8 sin BOM. Esperado: `escrito: ...`.
3. **Comprueba la idempotencia:** el mismo comando sin `--apply` debe imprimir `cambios: 0`.

Puntos a entender:
- El hook usa `startup|resume|clear|compact` para que el índice vuelva a inyectarse tras `/clear` y `/compact`.
- Si hay políticas de gobernanza (`allowManagedHooksOnly`), el hook debe pasar a *managed settings*; consúltalo con el administrador del equipo.
- **Mide el coste en contexto:** todo lo que se inyecta se paga en cada turno. Mantén `CLAUDE.md` corto y `MEMORY.md` en punteros de una línea.

## 8. `~/.claude/CLAUDE.md`: agregar el bloque entre marcadores

El paso 5 dejó el bloque ya listo (con las rutas reales) en `$HOME/.claude/vault-obsidian.block.md`. Va entre los marcadores `<!-- vault-obsidian:inicio -->` y `<!-- vault-obsidian:fin -->`.

| Caso | Qué hacer (con Edit, mostrando el diff y esperando confirmación) |
|---|---|
| No existe `CLAUDE.md` | Cópialo: `Copy-Item "$HOME/.claude/vault-obsidian.block.md" "$HOME/.claude/CLAUDE.md"` |
| Existe y ya tiene los marcadores | Reemplaza **solo** lo que hay entre los marcadores (inclusive) por el bloque nuevo |
| Existe sin marcadores | **Agrega** el bloque al final, tras una línea en blanco. No borres nada de lo existente |

Después elimina el archivo temporal: `Remove-Item "$HOME/.claude/vault-obsidian.block.md"`. El `CLAUDE.md` se carga en cada turno de todas las sesiones y cuesta tokens: el bloque es corto (~3 KB) a propósito.

## 9. Memoria automática: `MEMORY.md` y tipos de memoria

Un archivo por hecho en la carpeta `memory/` del proyecto, con frontmatter:

```markdown
---
name: <slug-corto>
description: <una línea; sirve para decidir relevancia>
metadata:
  type: user | feedback | project | reference
---
<el hecho; en feedback/project agrega **Why:** y **How to apply:**>
```

Y una línea por memoria en `MEMORY.md` (índice, sin contenido): `- [Título](archivo.md) — gancho`. Las entradas con detalle en el vault llevan 🔗 y solo un puntero.

| Tipo | Dónde vive |
|---|---|
| `feedback` (reglas de comportamiento, correcciones, preferencias) | **Solo memoria automática** |
| `project` / `reference` (arquitectura, estado, planes, hallazgos) | **Vault** + puntero de una línea en la memoria |
| `user` (rol, preferencias) | Memoria automática |

**`autoMemoryDirectory` (opcional).** Sin esta clave, cada directorio de trabajo tiene su propia memoria (`~/.claude/projects/<carpeta>/memory`). Fíjala solo si el usuario quiere que todas las sesiones carguen el mismo `MEMORY.md`:
- El nombre de `<carpeta>` es la ruta del proyecto con **todo carácter que no sea letra o número reemplazado por `-`** (los espacios, `:`, `\`, `&` también). Cálculo: `($PWD.Path -replace '[^A-Za-z0-9]','-')`. Ejemplo: `C:\Users\ana\Documents\Claude` → `C--Users-ana-Documents-Claude`.
- Se aplica con `--memory "<HOME>/.claude/projects/<carpeta>/memory"` en el paso 7. Si tras reiniciar la sesión no se carga el `MEMORY.md` de esa carpeta, quita la clave.

Si el equipo ya tenía memoria en otro directorio de proyecto, **cópiala** (no la muevas) a la carpeta elegida. Para **migrar al vault** lo que ya existe, sigue el paso 12.

## 11. Obsidian (lo hace la persona, no Claude)

1. Abre Obsidian → *Open folder as vault* → `<VAULT>`, para que cree `.obsidian/`. **No edites `.obsidian/` desde Claude ni desde scripts** mientras Obsidian esté abierto: lo sobrescribe.
2. *Settings → Core plugins → Templates*: carpeta de plantillas = `templates`. Plugins nativos útiles: Templates, Properties, Backlinks, Graph, Bookmarks.
3. **No conectes Obsidian Sync ni Publish** y no instales plugins beta (BRAT) ni de terceros que envíen datos fuera del equipo.

## 12. Migrar e indexar el contexto que Claude ya tenía (fase 2, opcional)

Hazla en una **sesión aparte** y con su propia aprobación del usuario, después de pasar la verificación del paso 10. Objetivo: que lo ya acumulado (memorias, notas sueltas, documentación propia) quede en el vault **bien indexado**, de modo que Claude lo encuentre rápido, lea solo lo necesario y no duplique. Ejecútala **una vez**, en lotes pequeños.

**Cómo busca Claude** (por eso importa cómo se escribe cada nota):
1. Al iniciar sesión recibe el índice del hook: por cada nota, **nombre + `resumen`** (solo las `activo`/`pausado` llevan resumen; las `cerrado`/`referencia` aparecen solo por nombre).
2. Elige la nota por nombre/resumen y la lee; empieza por `## Estado actual`.
3. Si el tema no figura, busca con `Grep` en el vault (frontmatter incluido).

**Pasos**
1. **Inventario (solo lectura).** Lista las fuentes: `~/.claude/projects/*/memory/*.md`, `CLAUDE.md` de proyectos y la documentación propia que el usuario quiera incorporar (runbooks, notas, traspasos). **No importes historiales de chat** (`history.jsonl`, transcripts): son ruido y encarecen la búsqueda.
2. **Respaldo.** Copia las memorias actuales a `<HOME>/.claude/backups/memoria-<fecha>/`. No se borra ni se edita ningún original hasta el paso 8.
3. **Clasificación (tabla para aprobar).** Antes de escribir, muestra al usuario una tabla `fuente → destino → tipo → nota propuesta` y espera su visto bueno:

   | Contenido de la fuente | Destino |
   |---|---|
   | Reglas de comportamiento, correcciones, preferencias (`feedback`, `user`) | Se quedan en la memoria automática |
   | Arquitectura, estado de despliegues, planes, bloqueos, traspasos, hallazgos (`project`, `reference`) | **Nota del vault** + puntero de una línea en la memoria |
   | Credenciales, tokens, datos de clientes/proveedores/personal | **No se migra.** Se anonimiza o se omite |
   | Duplicados o contenido caduco | Se fusiona con la nota existente o se descarta |

4. **Barrido de confidencialidad.** Antes de escribir cada nota, busca en el texto `password|passwd|pwd|secret|token|apikey|api_key|bearer|BEGIN .*PRIVATE KEY|connection ?string` y datos personales o de clientes (identificadores fiscales o personales, facturas). Si hay coincidencias: omitir o sustituir por un marcador (`<credencial en gestor de secretos>`).
5. **Crear una nota por tema** con la plantilla de `tipo` correspondiente (sistema / proyecto / análisis / referencia / guía), con Write. Reglas para que se encuentren rápido:
   - **Nombre** del archivo: `kebab-case`, descriptivo y **único** en todo el vault (`kafka-prod-k8s`, no `notas` ni `pendientes`); incluye sistema y entorno si aplica. Es lo único que ve Claude de las notas cerradas.
   - **`resumen` (≤100 caracteres):** lleva las palabras que alguien buscaría (sistema, tecnología, entorno) **y el estado real** (`"Kafka prod KRaft 3 brokers; falta mirror al segundo clúster"`). Evita frases vagas ("notas de Kafka").
   - **`estado`:** `activo` si hay trabajo abierto, `pausado` si espera una decisión, `cerrado`/`referencia` si no. Solo `activo`/`pausado` suben su resumen al índice inyectado.
   - **`tags`:** 3 a 6, en minúsculas y **del mismo vocabulario en todas las notas** (`kafka`, `k8s`, `produccion`); permiten buscar con `Grep` por `tags:.*kafka`.
   - **`area`** = ruta relativa de la carpeta; **una** nota principal por sistema o proyecto, no una por conversación.
   - **Wikilinks:** `**Área:** [[<índice de la carpeta>]]` y al menos 2 enlaces a notas relacionadas (1 en subnotas).
   - **`## Estado actual` primero** (≤ ~40 líneas): estado, decisiones vigentes, próximo paso, bloqueos. El historial va debajo o en subnotas.
   - Si la fuente supera ~20 KB: nota principal corta + subnotas `detalle` con `vault-split-note.js` (paso 6).
6. **Puntero en la memoria automática.** Reemplaza el contenido de cada memoria `project`/`reference` migrada por 2 a 4 líneas y la ruta de la nota, y actualiza la línea de `MEMORY.md` (`- [Título](archivo.md) 🔗 — gancho`). Así no hay dos versiones del mismo hecho.
7. **Regenerar y medir:** ejecuta T2 y T6 del paso 10 y **corrige todos los avisos**. El índice inyectado debe quedar **bajo 9 500 caracteres**; si lo supera, el script pasa a mostrar solo nombres. Para reducirlo: resúmenes más cortos, marcar como `referencia` lo que no tiene trabajo abierto, o partir un área grande en subcarpetas. Referencia: ~90 notas ≈ 6 600 caracteres.
8. **Prueba de búsqueda (aceptación).** Elige 3 temas migrados y, en una **sesión nueva**, pregúntalos sin dar la ruta. Criterio: Claude menciona la nota correcta y responde sin leer más de 1 a 2 notas. Si falla, mejora el `resumen`, el nombre o los `tags` de esa nota (no agregues más texto al cuerpo). Solo entonces se pueden archivar los originales (moverlos a la carpeta de respaldo, no borrarlos).
9. **Mantenimiento.** A partir de aquí, cada hallazgo nuevo se escribe **actualizando** la nota existente (`estado`, `actualizado`, `resumen`) y ejecutando `vault-indices.js`; si una nota crece más de ~20 KB, se divide.

## 13. Solución de problemas

| Síntoma | Causa probable | Acción |
|---|---|---|
| El índice no aparece al iniciar sesión | Hook mal escrito o `settings.json` inválido | Ejecuta a mano el comando del hook; repite T3 |
| `Índice del vault ... no disponible` | Error al generarlo (ruta del vault inexistente, frontmatter roto) | Mira el mensaje; revisa la ruta que usa el hook |
| Una nota sale en el índice "sin resumen" aunque tiene frontmatter | Se escribió con otra codificación (ANSI, BOM o UTF-16) | Reescríbela con Write; el script ya tolera BOM y UTF-16, pero ANSI daña los acentos |
| `Cannot find module '~/...'` | `~` no se expande en Windows PowerShell 5.1 | Usa `"$HOME/..."` entre comillas |
| `HASH DISTINTO` | La guía se editó o se pegó con errores | Detente; recupera la guía original o recalcula con `--hashes` si fue un cambio intencional |
| `DISTINTO, no se toca` | Ya existe un archivo propio con ese nombre | Pregunta al usuario; respalda antes de reemplazar |
| `JSON inválido` en `settings.json` | El archivo ya estaba roto o tiene BOM | Detente y pide al usuario corregirlo; no lo repares tú |
| Aviso `area=... no coincide con la carpeta` | `area:` del frontmatter distinto de la ruta relativa | Corrige el frontmatter |
| Claude pide permiso en cada lectura o escritura del vault | Falta `permissions.allow` o la ruta no coincide | Revisa que `<VAULT>` sea idéntica (mayúsculas, `/`); para escritura, repite el paso 7 con `--write` |
| Notas > 20 KB lentas de cargar | Historial acumulado en la nota principal | `vault-split-note.js` |
| El vault tiene conflictos o archivos bloqueados | Está en una carpeta sincronizada (OneDrive) | Muévelo a una carpeta no sincronizada (paso 2) |

````js
function readText(f) {
  const b = fs.readFileSync(f);
  if (b[0] === 0xFF && b[1] === 0xFE) return b.slice(2).toString('utf16le');
  if (b[0] === 0xEF && b[1] === 0xBB && b[2] === 0xBF) return b.slice(3).toString('utf8');
  return b.toString('utf8');
}
function writeIfChanged(file, content) {
  if (!fs.existsSync(file) || fs.readFileSync(file, 'utf8') !== content) fs.writeFileSync(file, content, 'utf8');
}
const ESTADOS_VISIBLES = { activo: 'activo', pausado: 'pausado', cerrado: 'cerrado' };

function parseFrontmatter(text) {
  const lines = text.split(/\r?\n/);
  if (lines[0] !== '---') return { fm: {}, body: text };
  const fm = {};
  let i = 1, lastKey = null;
  for (; i < lines.length && lines[i] !== '---'; i++) {
    const m = lines[i].match(/^([A-Za-zÀ-ÿ_][\w-]*):\s*(.*)$/);
    if (m) { lastKey = m[1]; fm[lastKey] = m[2]; }
    else if (lastKey && /^\s*-\s+/.test(lines[i])) fm[lastKey] += (fm[lastKey] ? ', ' : '') + lines[i].replace(/^\s*-\s+/, '');
  }
  return { fm, body: lines.slice(i + 1).join('\n') };
}
const unquote = s => (s || '').trim().replace(/^"(.*)"$/, '$1').replace(/\\"/g, '"');
const rel = p => path.relative(VAULT, p).split(path.sep).join('/');
const isIndex = f => path.basename(f, '.md') === path.basename(path.dirname(f));

function scan(dir) {
  const entries = fs.readdirSync(dir, { withFileTypes: true }).filter(e => !e.name.startsWith('.'));
  const subdirs = entries.filter(e => e.isDirectory() && !CARPETAS_EXCLUIDAS.has(e.name)).map(e => path.join(dir, e.name)).sort();
  const notes = entries.filter(e => e.isFile() && e.name.endsWith('.md'))
    .map(e => path.join(dir, e.name))
    .filter(f => !isIndex(f) && !(dir === VAULT && path.basename(f) === 'Indice.md'))
    .map(f => {
      const { fm, body } = parseFrontmatter(readText(f));
      // Enlaces a otras notas, sin contar la línea "**Área:** [[índice]]".
      const enlaces = (body.replace(/^\*\*Área:\*\*.*$/m, '').match(/\[\[[^\]]+\]\]/g) || []).length;

    })
    .sort((a, b) => a.name.localeCompare(b.name));
  return { dir, subdirs, notes };
}

function countNotes(dir) {

  return s.notes.length + s.subdirs.reduce((n, d) => n + countNotes(d), 0);

function descOf(dir) {
  const r = rel(dir);
  if (extraDesc[r]) return extraDesc[r];
  const idx = path.join(dir, path.basename(dir) + '.md');
  if (fs.existsSync(idx)) return unquote(parseFrontmatter(readText(idx)).fm.descripcion);
  return '';
}

const noteLine = n => `- [[${n.name}]] — ${n.resumen || '*(sin resumen)*'}${ESTADOS_VISIBLES[n.estado] ? ` · \`${n.estado}\`` : ''}`;
const todas = [];
const all = todas;
const warnings = [];

function writeIndex(dir, parentName) {
  const s = scan(dir);
  const name = path.basename(dir);
  const desc = descOf(dir);
  const out = ['---', 'tags: area-index', `descripcion: "${desc.replace(/"/g, '\\"')}"`, 'generado: "auto — ~/.claude/scripts/vault-indices.js; no editar a mano"', '---', '', `# ${name.replace(/-/g, ' ')}`, ''];
  if (desc) out.push(desc, '');
  if (s.subdirs.length) {
    out.push('## Subáreas', '');
    for (const d of s.subdirs) out.push(`- [[${path.basename(d)}]] — ${descOf(d)} (${countNotes(d)} notas)`);
    out.push('');
  }
  if (s.notes.length) {
    out.push(s.subdirs.length ? '## Notas generales' : '## Notas', '');
    for (const n of s.notes) {
      out.push(noteLine(n));
      all.push({ ...n, indice: name, carpeta: rel(dir) });

    }
    out.push('');
  }
  out.push(`⬅ [[${parentName}]]`, '');
  writeIfChanged(path.join(dir, name + '.md'), out.join('\n'));

}
````

````js
// Fusiona la configuración del vault en settings.json de forma idempotente y con respaldo. Solo librería estándar.
// Uso: node vault-settings.js <settings.json> <VAULT> [--write] [--memory <carpeta>] [--apply]   |   node vault-settings.js --selftest
// Sin --apply no escribe nada: imprime los cambios y "cambios: N". Con --apply guarda un respaldo <archivo>.bak-<fecha>.
// Códigos de salida: 0 correcto, 1 JSON inválido, 2 uso incorrecto.
const fs = require('fs'), os = require('os'), path = require('path'), assert = require('assert');

function plan(settings, vault, home, opts) {
  const s = JSON.parse(JSON.stringify(settings)), cambios = [];
  const v = vault.replace(/\\/g, '/').replace(/\/+$/, ''), h = home.replace(/\\/g, '/').replace(/\/+$/, '');
  s.permissions = s.permissions || {};
  s.permissions.allow = s.permissions.allow || [];
  for (const t of ['Read', 'Edit', 'Grep'].concat(opts.write ? ['Write'] : [])) {
    const regla = `${t}(${v}/**)`;
    if (!s.permissions.allow.includes(regla)) { s.permissions.allow.push(regla); cambios.push('permissions.allow + ' + regla); }
  }
  s.hooks = s.hooks || {};
  s.hooks.SessionStart = s.hooks.SessionStart || [];
  if (!Array.isArray(s.hooks.SessionStart)) throw new Error('hooks.SessionStart no es un arreglo');
  const existe = s.hooks.SessionStart.some(g => (g.hooks || []).some(x => /vault-indices\.js/.test(x.command || '')));
  if (!existe) {
    s.hooks.SessionStart.push({ matcher: 'startup|resume|clear|compact', hooks: [{ type: 'command', command: `node "${h}/.claude/scripts/vault-indices.js" --llm`, timeout: 30 }] });
    cambios.push('hooks.SessionStart + vault-indices.js --llm');
  }
  if (opts.memory && !s.autoMemoryDirectory) { s.autoMemoryDirectory = opts.memory; cambios.push('autoMemoryDirectory = ' + opts.memory); }
  return { s, cambios };
}

function selftest() {
  const h = 'C:/Users/ana', v = 'C:/V';

    fs.mkdirSync(path.dirname(file), { recursive: true });
    fs.writeFileSync(file, JSON.stringify(r.s, null, 2) + '\n', 'utf8'); // UTF-8 sin BOM
    console.log('escrito: ' + file);
  }
  return 0;
}

if (process.argv.includes('--selftest')) selftest(); else process.exitCode = main(process.argv.slice(2));
````

## Anexo B: extractor (el único archivo que se transcribe a mano)

Se crea en el paso 5.1 y se verifica con `Get-FileHash` contra el `sha256=` de este marcador.

<!-- archivo: claude/scripts/vault-extraer.js sha256=2d18bf515df18e74e4a4dee78edb7909b13ab2389034c0634dde26f59f8fd948 -->
````js
// Extrae los archivos del Anexo A de la guía verificando el SHA256 de cada uno. Solo librería estándar.
// Uso: node vault-extraer.js <guia.md> <CLAUDE_DIR> <VAULT> [--apply | --hashes]
// Sin --apply solo informa (nuevo / igual / DISTINTO). --hashes imprime los hashes reales (para mantener la guía).
// Verifica TODOS los hashes antes de escribir nada. Códigos de salida: 0 correcto, 1 hash distinto, 2 archivo existente distinto o uso incorrecto.
const fs = require('fs'), path = require('path'), crypto = require('crypto');
const [guia, claudeDir, vault] = process.argv.slice(2).filter(a => !a.startsWith('--'));
const apply = process.argv.includes('--apply'), hashes = process.argv.includes('--hashes');
if (!guia || !claudeDir || !vault) { console.error('uso: node vault-extraer.js <guia.md> <CLAUDE_DIR> <VAULT> [--apply | --hashes]'); process.exit(2); }
const texto = fs.readFileSync(guia, 'utf8').replace(/^﻿/, '').replace(/\r\n/g, '\n');
const re = /<!-- archivo: (claude|vault)\/(\S+) sha256=([0-9a-f]{64}) -->\n````\w*\n([\s\S]*?)\n````/g;
const sha = s => crypto.createHash('sha256').update(s, 'utf8').digest('hex');
const fwd = p => p.replace(/\\/g, '/');
const items = [...texto.matchAll(re)].map(([, raiz, rel, esperado, cuerpo]) => ({ raiz, rel, esperado, cuerpo, real: sha(cuerpo + '\n') }));
if (!items.length) { console.log('SIN ARCHIVOS: la guía no tiene el Anexo A'); process.exit(2); }
if (hashes) { items.forEach(i => console.log(`${i.raiz}/${i.rel} sha256=${i.real}`)); process.exit(0); }
const malos = items.filter(i => i.real !== i.esperado);
if (malos.length) { malos.forEach(i => console.log(`HASH DISTINTO ${i.raiz}/${i.rel}`)); process.exit(1); }
let codigo = 0;
for (const i of items) {
  const destino = path.join(i.raiz === 'claude' ? claudeDir : vault, i.rel);
  const contenido = i.cuerpo.replace(/\{\{CLAUDE_DIR\}\}/g, fwd(claudeDir)).replace(/\{\{VAULT\}\}/g, fwd(vault)) + '\n';
  const existe = fs.existsSync(destino);
  if (existe && fs.readFileSync(destino, 'utf8') === contenido) console.log('igual   ' + destino);
  else if (existe) { console.log('DISTINTO, no se toca  ' + destino); codigo = 2; }
  else { console.log((apply ? 'escrito ' : 'nuevo   ') + destino); if (apply) { fs.mkdirSync(path.dirname(destino), { recursive: true }); fs.writeFileSync(destino, contenido, 'utf8'); } }
}
console.log(codigo ? 'REVISAR' : `OK ${items.length} archivos`);
process.exit(codigo);
````
